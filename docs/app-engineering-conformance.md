# App-engineering conformance: 3D Print Pricing

The record that this app was held against the 111 topics of App-Guidance's
[`shared/framework/app-engineering/`](https://github.com/Flux76HQ/App-Guidance/blob/main/shared/framework/app-engineering/README.md),
as its baseline asks (section 18), and the input for a performance, security and operations review. It was started from
the conformance template in that repository.

How to read it:

- **Status**: `applies` (in place, with evidence), `partial` (the core is in place and a named part is not: `Gap:` in the same cell),
  `not-now` (not in place or not assessed, with the reason and when it is looked at again), `n/a` (does not apply to this app, with the reason).
- **Evidence** was read from the code, the tests and the documents of this repository. The performance numbers were measured
  (`docs/performance.md` says how, and what that does not show). Nothing here was measured on the owner's running installation.
- **Control** names the test, CI job or file that keeps the answer true. A test file without a job runs in `backend-tests`. An empty
  cell means the topic is guidance here, not something a check guards.
- The app is one container that its owner hosts, for one small business and a handful of users. Many topics are `n/a` for that
  reason, and several gaps are the operator's to close (the proxy, TLS, copies of the backups, a monitor). They are named so that
  nobody assumes the app does them.

`scripts/test_conformance.py` (job `backend-tests`) checks that every topic is answered, as App-Guidance's own validator does, and
that every file named here exists. It cannot check that an answer is true. Answer the rows again after a large change and before a public release.
